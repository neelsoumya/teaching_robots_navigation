ROS 2 Middleware Architecture & Operational Principles

This section presents the modular, decentralized layer structure of ROS 2 built upon the Data Distribution Service (DDS) industry standard. Unlike ROS 1, which relied on a single centralized rosmaster, ROS 2 enables real-time peer-to-peer data transport with dynamic discovery, deterministic node state management, and strict domain isolation across distributed networks.

Dynamic Discovery & Domain Isolation

ROS 2 uses the Simple Discovery Protocol (SDP) over UDP multicast. Nodes automatically discover peer publishers and subscribers on the same local network subnet without needing a central server.

Core Communication Primitives & Quality of Service (QoS)

Nodes in the ROS Graph interact through four foundational primitives: Topics, Services, Actions, and Parameters. Selecting the correct primitive and configuring appropriate DDS Quality of Service (QoS) profiles dictates the real-time reliability and responsiveness of sensor data streams and control loops.

Local Trajectory Controller Plugin Comparison

DWB Controller (Trajectory Critic) Differential / Omnidirectional

Evaluates discrete velocity sample grids over forward time horizons against multi-objective trajectory critics. Lightweight CPU utilization, but susceptible to local minima in tight spaces.

MPPI Controller (Model Predictive Path Integral) GPU / Multi-Threaded CPU

Samples thousands of stochastic trajectory candidates in parallel. Delivers smooth motion around dynamic obstacles across differential, Ackermann, and legged robots.

Regulated Pure Pursuit Controller Ackermann / Differential

Scales forward linear velocity based on path curvature while tracking dynamic lookahead points. Highly stable and predictable along fixed industrial corridors.

Common Student Technical Pitfalls & Resolutions

1. Simulation Time Desynchronization

Symptom: Buffer drops, missing laser scans, tf lookup failures inside RViz2.

Remediation: Pass use_sim_time:=True globally across all node launches during Gazebo runs.

2. Cross-Talk on Shared Subnets

Symptom: Workstations receive unexpected scans or conflicting transform trees from neighbors.

Remediation: Export a unique integer domain ID per student shell: export ROS_DOMAIN_ID=15.

3. Transform Tree Loops

Symptom: System crashes in tf2_ros with cyclic parent frame errors.

Remediation: Never link map directly to base_link. Enforce single-parent chain: map → odom → base_link.
