Fixing odometry with landmarks and an alpha-beta filter

A teaching page: four ways to understand the idea, then a simulator to play with.

Walking along a dark corridor. You count your steps to know where you are. But your steps are not exactly the length you think they are, so the error slowly builds up. This is odometry drift.

Every so often you pass a door with a number on it. You know exactly where that door is on the map. You glance at it and say: “my step counting says I’m at 9.4 m, but the door says I’m at 9.0 m.” You now have a disagreement. Who do you believe?

The alpha-beta filter says: believe a bit of both. Move your estimate part of the way toward the landmark (that’s α), and also use the disagreement to learn that your steps are systematically too long (that’s β), so future steps are corrected before they drift.

Each time step has three beats: predict, look, correct.

 predict (from odometry)      look (landmark)        correct
 ─────────────●────────▶      ──────────●             ───────●───▶
  old estimate  + step         measured position       blend:  pred + α · (measured − pred)

 residual r = measured − predicted    (the "surprise")
 r large and positive → odometry is under-reporting; r negative → over-reporting
  • Odometry = smooth but drifts forever. Great short-term, bad long-term.
  • Landmark = noisy but never drifts, and only available sometimes. Bad short-term, great long-term.
  • The filter combines each one’s strength. α sets how much you trust a single landmark reading; β sets how fast you learn the odometry’s habitual error.

State: position estimate x and a per-step odometry error estimate b. Odometry gives a step u. A landmark fix gives a position z (landmark position minus the measured offset to it).

Predict:   x⁻ = x + u + b
Residual:  r  = z − x⁻            (only when a landmark is visible)
Correct:   x  = x⁻ + α r
           b  = b  + β r

No landmark visible?  x = x⁻, b unchanged.  (pure odometry, with the learned fix)

Textbook form: predict x⁻ = x + v·dt, then x = x⁻ + α r and v = v + (β/dt) r. Here b plays the role of the velocity-error term, so it is the same filter, with the velocity state replaced by the odometry error. Typical values: 0 < β ≤ α ≤ 1, and β is much smaller than α.

  • α = 0: ignore landmarks completely (pure odometry). α = 1: jump straight to the landmark reading, noise and all.
  • β = 0: never learn the drift, so each landmark only resets the position. β too big: the filter chases noise and wobbles.
  • It is a fixed-gain cousin of the Kalman filter: the Kalman filter computes α and β from the noise levels; here you tune them by hand.
x, b = 0.0, 0.0
alpha, beta = 0.3, 0.02

for u, z in zip(odometry_steps, landmark_fixes):  # z is None if no landmark seen
    x_pred = x + u + b                 # 1. predict
    if z is not None:
        r = z - x_pred                 # 2. residual
        x = x_pred + alpha * r         # 3. correct position
        b = b + beta * r               #    learn odometry error
    else:
        x = x_pred

In ROS 2 the same logic sits in a node that subscribes to /odom and a landmark detection topic, and publishes the corrected pose (often as the map→odom transform).

Things to try with students

  1. Set α = 0. Predict what the blue line will do, then run it. (It matches the red one.)
  2. Set α = 1 and raise landmark noise. Why does the blue error become jittery?
  3. Keep α = 0.3 and compare β = 0 with β = 0.02. Watch the error between landmarks: the drift slope flattens once b is learned.
  4. Raise β to 0.3. What goes wrong, and why?
  5. Shrink the sensing range to 0.5 m. How long can the filter coast between landmarks?
  6. Discussion: when would you want the Kalman filter’s adaptive gains instead of fixed α, β?
